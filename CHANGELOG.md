## [Unreleased]

### Added

- Animated README card (`#53`, partial): the README is a single field-notebook SVG card (light and dark, CSS animations, reduced-motion aware) generated by `ml/scripts/build_readme_card.py` from the model registries, with the full text below it. Phase table and API start command brought up to date.
- Release APK signing (`#76`, CI part): the `withReleaseSigning` config plugin makes release builds sign with an upload keystore whose path and passwords come from environment variables at Gradle time (debug key as fallback) and derives `versionCode` from the version (`0.5.0` -> `500`). `release.yml` decodes the `ANDROID_KEYSTORE_BASE64` secret into the runner's temp directory, verifies the APK certificate with `apksigner` (shown in the job summary), deletes the keystore afterwards, warns and renames the file when it falls back to the debug key, builds the APK for every tag from `v1.0.0` on, and can be run manually to build and download the APK without publishing a release. `docs/SETUP_SERVICES_ES.md` §10.5 explains creating the keystore and the four secrets.
- Plot microclimate from Open-Meteo (`#42`): `GET /weather/microclimate?latitude=&longitude=` (authenticated, `60` requests per user per hour) returns hourly temperature, relative humidity, precipitation and dew point and daily aggregates (min/mean/max temperature, rain, rain hours, humidity) for `14` past and `7` forecast days by default (`America/Costa_Rica`), with the CC BY 4.0 attribution in every response. Coordinates are rounded to 2 decimals (about 1.1 km) before they are sent to Open-Meteo; responses are cached for an hour per rounded location and the last copy (up to 24 h old) is served with `stale: true` when Open-Meteo fails. `httpx2` is now a declared runtime dependency.
- Weather disease risk (`#78`, coffee and cacao): `GET /plots/{plot_id}/weather-risk?latitude=&longitude=` returns, for the plot's crop, a `low`/`moderate`/`high` level from the last 7 and next 7 days of Open-Meteo data, the favourable dates, every threshold with its basis (`source` or `provisional`) and citation, a disclaimer and the CC BY 4.0 attribution. Coffee leaf rust uses mean 21.6-23.6 C, mean humidity above 80 % and leaf wetness (Capucho et al., 2013; ICAFE, 2020); cacao moniliasis uses at least 6 hours with humidity above 80 % and temperature above 24 C (CATIE, 2021). Banana black Sigatoka returns `insufficient_evidence` because no verified numeric threshold was found.

### Fixed

- Release bundling on a clean install (`#76`): the app now declares `query-string`, which `expo-router` `4.0.22` requires at load time without listing it as a dependency.

## [0.5.0] - 2026-11-08
- Explanations saved per scan and citation badges (`#74`): every explanation shown for a scan is copied to a new SQLite table `scan_explanations`, and Scan Detail falls back to that copy when the API cannot be reached, so it stays readable in airplane mode even after switching the app language (a note says which language it was saved in). Citations are now badges (`publisher · section`) that expand on tap to the full reference (title, publisher, year, pages) with an Open source button. The Result screen waits until the scan is saved before requesting, so one diagnosis spends one request.
- Cited explanations in the app (`#37`): Result and Scan Detail show an explanation card for confident, non-healthy diagnoses with a skeleton while loading, the summary, numbered next steps, the cited source and section (publisher, year, pages), an AI disclaimer and, when read from the phone, a "saved offline" note. `app/src/services/explanations.ts` sends only `(crop, disease_class, severity, language)` to `POST /explanations` through TanStack Query (`@tanstack/react-query` `5.104.5`) and keeps answers in a new SQLite table `explanations` keyed by those four values, read first so answers stay available offline and repeated diagnoses do not spend the hourly quota. `not_covered` refusals are not kept. Offline, signed-out, rate-limited (`429`) and unavailable states have their own `es`/`en` messages, with a retry button where it helps.
- Explanation cache, privacy guard and rate limit (`#50`): `POST /explanations` answers are cached in process by `(crop, disease_class, severity, language)` only, so repeated diagnoses (from any user) skip Gemini; concurrent misses on one key make a single call, and model failures and refusals are not cached. The service refuses classes outside the crop's model taxonomy, and tests check every supported prompt contains only those four values (no names, emails, uid, coordinates or request headers). Each user (Firebase `uid`, not IP) may send `20` requests per hour (`slowapi`); request `21` gets `429 rate_limited` with `Retry-After`. Unauthenticated and invalid requests do not spend quota.
- `POST /explanations` (`#36`): for an authenticated user and a diagnosis `(crop, disease_class, severity, language)` only, retrieves up to 4 passages from the local RAG index and asks Gemini (`google-genai`, `GEMINI_MODEL`) for a plain-language summary and next steps as JSON, citing passages by id. The response lists `source_title`, `publisher`, `section`, pages and URL for each cited section. It declines (`covered: false`) for healthy plants, when no passage matches, or when the model does not cite a provided passage; it returns `503` when Gemini or the index is unavailable. Request bodies reject any other field.
- Local RAG index and retriever (`#49`): `api/scripts/build_rag_index.py` turns `chunks.jsonl` into a byte-reproducible TF-IDF index (`api/.cache/rag/index.json`), and `RagIndex.retrieve(crop, disease_class, query, k)` filters by crop and disease class and ranks by cosine similarity, keeping source, section, pages and URL for citations. Queries are built only from `(crop, disease_class, severity)` with bilingual keywords, weighted toward symptoms for `watch` and control for `actNow`. Sections can now `exclude` interleaved blocks, which removes the reference list printed mid-column in the CORBANA bulletin.
- Cacao and banana RAG sources (`#73`): CATIE's *Guía para el manejo integrado de enfermedades en el cultivo de cacao* (2021) for `monilia` and `black_pod`, CORBANA's *Manejo de la Sigatoka negra* bulletin (2011) for `black_sigatoka`, and FAO's Fusarium TR4 technical manual (2014, English) for `fusarium_wilt`, with pinned checksums. Every disease class of coffee, cacao and banana now has cited chunks (`86` in total), checked by a test. The chunker removes line-break hyphens for sources marked `soft_hyphens` and spaces before punctuation.
- Agronomic document fetcher and section chunker for RAG (`#35`): `api/rag_sources.toml` lists official sources with pinned SHA-256 checksums and the sections to index; `api/scripts/fetch_agronomic_docs.py` downloads them into the git-ignored `api/.cache/rag/`, extracts PDF text (`pypdf` + `fonttools`, new `rag` extra), and writes `chunks.jsonl` with `(source, section, pages, crop, disease_classes)` metadata and a per-class coverage report. The first source is ICAFE's *Guía técnica para el cultivo de café* (2020), covering all five coffee disease classes.
- End-to-end multi-tenant sync contract verification and Render deployment configuration (`#48`): shared fixture-based contract tests (`app/src/services/fixtures/sync_contract.json`, validated by `api/tests/test_contract.py` and `app/src/services/__tests__/contract.test.ts`) asserting 100% schema and field parity for farms, plots, and scans, idempotent re-sync and tenant isolation; and `render.yaml` Blueprint specification for deploying the FastAPI backend to Render's free tier with uv, Python 3.12, health check (`/health`), auto-deploy from `main`, and secret files for Firebase Admin.
- Account settings and local data claiming (`#72`): the Settings account card shows the signed-in email, last sync time (persisted in AsyncStorage), pending change count, a Sync now button, and Sign out with a confirmation dialog (also used on the Account screen). On the first sign-in on a device, anonymous local farms, plots and scans are claimed for that account and synced; records the API refused earlier are re-queued. Data synced by a different account is left untouched.
- Android sync engine (`#47`): `app/src/services/sync.ts` pushes pending farms, plots and scans to the API in dependency order (farms, plots, scans in batches of `100`, then deletions), falls back from `POST` to `PATCH` on `409`, treats `404` on delete as done, marks API-refused records `failed`, and leaves everything `pending` when a run stops offline or on a `401`/`5xx`. Outcomes are recorded only if the row was not edited during the run. `app/src/services/cloudinary.ts` resizes scan photos to a `1280 px` longer side and uploads them with API-signed parameters. Sync runs on sign-in, when connectivity returns (`@react-native-community/netinfo`), on app foreground, and on tapping the new Home sync pill, which pulses while syncing and morphs into a checkmark (static with reduce motion).
- Firebase Auth email/password in the app (`#34`): `app/src/services/auth.ts` (Firebase JS SDK with AsyncStorage session persistence, lazily initialized from `EXPO_PUBLIC_FIREBASE_*`, error codes mapped to `es`/`en` messages), a Zustand session store, Sign In, Sign Up and Account screens with form validation, a `TextField` UI primitive, a Settings account card, and `app/src/services/api.ts`, which attaches `Authorization: Bearer <idToken>` when signed in and retries once with a refreshed token on `401`. Diagnosis, history and local farms keep working without an account or without Firebase configured.
- Idempotent batch `POST /scans/sync` (client UUIDs, last write wins on `updated_at`, tombstones, per-item `created`/`updated`/`unchanged`/`rejected` results), `GET /scans` with `farm_id`/`plot_id`/`crop` filters, and `POST /uploads/scan-signature` returning signed Cloudinary upload parameters scoped to `users/{uid}/scans` with a `1280 px` limit, plus User A vs. User B isolation tests (`#46`).
- `CRUD /farms` and `CRUD /plots` in `api/` with client-generated UUID v4 IDs, `ownerUid` filtering on every Firestore read and write (`OwnedRepository` over a `DocumentStore` protocol), soft deletes with farm-to-plot cascade, `404` for other users' records, `409` for duplicate IDs, and User A vs. User B isolation tests (`#33`).
- FastAPI core in `api/`: `create_app` factory (`healthycropping_api.main:app`), environment settings, public `GET /health`, Pydantic v2 schemas, structured `{"error": {"code", "message"}}` responses, CORS, a Firebase ID token verification dependency (`firebase-admin`) protecting `GET /me` (`401` for missing, malformed, or expired tokens), and deny-all `firestore.rules` with `firebase.json` (`#32`).
- Multi-crop offline diagnosis in the app: banana model registry bundled in `app/src/ml/models/banana/`, banana selectable on the Home screen next to coffee and cacao, with tests for registry parity, model resource names, and the coming-soon state for crops without a model (`#31`).
- Float16 TFLite banana model export (`ml/scripts/export_banana_tflite.py`, `ml/models/banana/banana_v0.1.0_fp16.tflite`, `6.06 MB`, `97.50%` test accuracy with `0.00 pp` drop vs Keras and `100.0%` top-1 agreement), `--threshold-floor` export option, confidence threshold `0.80` (`98.45%` test precision at `97.0%` coverage), `ml/models/banana/registry.json`, and Banana Model Card (`docs/MODEL_CARD.md` §4) (`#71`).
- Banana `MobileNetV3-Large` frozen baseline (`97.00%` test accuracy, `0.9676` Macro-F1) and top-30 fine-tuned model (`97.50%` test accuracy, `0.9731` Macro-F1), CLI script (`ml/scripts/train_banana.py`), per-source evaluation (`ml/scripts/evaluate_by_source.py`), confusion matrices, and Grad-CAM visual explanations in `docs/EXPERIMENTS.md` (`#30`).
- Banana leaf dataset pipeline: BananaLSD (`OriginalSet` only, CC BY 4.0) and NM-AIST Banana Leaves Imagery (Zenodo `7670326`, CC BY 4.0) downloaders, HTTP Range extraction of image subsets from multi-gigabyte ZIP archives (`ml/src/healthycropping_ml/remote_zip.py`), `ml/configs/banana.yaml`, `ml/scripts/prepare_banana.py`, and the data report (`docs/data_reports/banana.md`, `docs/assets/data_reports/banana_grid.png`): `1,313` deduplicated images (`391` `healthy`, `622` `black_sigatoka`, `300` `fusarium_wilt`) across `770` groups with zero cross-split leakage (`#29`).
- Float16 TFLite cacao model export (`ml/scripts/export_cacao_tflite.py`, `ml/models/cacao/cacao_v0.1.0_fp16.tflite`, `6.06 MB`, `91.73%` test accuracy with `0.00 pp` drop vs Keras and `100.0%` top-1 agreement), validation-calibrated confidence threshold `0.51` (`90.15%` val precision), `ml/models/cacao/registry.json`, and Cacao Model Card (`docs/MODEL_CARD.md` §3) (`#70`).
- Cacao `MobileNetV3-Large` frozen baseline (`87.47%` test accuracy, `0.7946` Macro-F1) and top-30 fine-tuned model (`91.73%` test accuracy, `0.8502` Macro-F1, `0.9532` `healthy` F1, `0.8553` `monilia` F1, `0.7419` `black_pod` F1), CLI script (`ml/scripts/train_cacao.py`), confusion matrices (`docs/assets/confusion_matrices/cacao_*.png`), and Grad-CAM visual explanations (`docs/assets/gradcam/cacao_gradcam.png`) in `docs/EXPERIMENTS.md` (`#28`).
- Cacao pod dataset downloaders (`ml/scripts/download_cocoamonilia.py`, `ml/scripts/download_unab_cacao.py`), configuration (`ml/configs/cacao.yaml`), YOLO bounding-box pod cropper and preparation pipeline (`ml/scripts/prepare_cacao.py`), dataset report (`docs/data_reports/cacao.md`), and `224x224` sample grid (`docs/assets/data_reports/cacao_grid.png`) combining CocoaMoniliaDataSet (CC BY 4.0) and UNAB Cocoa Diseases (ODbL v1.0) into `2,646` deduplicated samples across `1,367` grouped tree/photo IDs (`#27`).

### Changed

- The Render blueprint (`#124`) now builds the RAG index on every deploy (`uv sync --frozen --no-dev --extra rag`, `scripts/fetch_agronomic_docs.py`, `scripts/build_rag_index.py --check`, which fails the build if a disease class has no passage) and declares `GEMINI_API_KEY` and `GEMINI_MODEL` (`sync: false`); the Spanish setup guide lists both.
- `README.md` and `app/README.md` now match the verified project state: an "in active development, no APK yet" note, measured test Macro-F1 (`0.729` coffee, `0.850` cacao, `0.973` banana) instead of unverified targets, float16-only export, a phase table aligned with `docs/PLAN.md`, and sync, RAG, Render deployment and APK distribution marked as in progress or planned (`#110`).

### Fixed

- Accessibility audit (`#52`): light `textTertiary` (captions, placeholders, disclaimers) darkened from `3.9-4.1:1` to `>= 6.2:1`; light banana accent darkened so white chip text reaches `4.99:1`; new `controlBorder` token gives inputs and checkboxes `>= 3:1` outlines; the Analyzing card no longer hardcodes white (dark mode text was `1.04:1`). Every delete and icon button is at least `48 dp`, icon glyphs are hidden from TalkBack behind translated labels, chips are radios with `checked` state, photos and the onboarding progress have labels, Sheet and Toast close labels are translated, History's open and delete targets are no longer nested, screen transitions honor reduced motion, and fixed-height headers and inputs grow with large fonts.
- Scan photos are copied from the volatile camera cache into the app's document directory (`expo-file-system`), and SQLite foreign keys are enforced on every connection (`#101`).
- On-device model loading: bundle registered TFLite models as Android raw resources via the `app/plugins/withTfliteModels.js` config plugin (SHA-256 verified), load them by resource name, route cacao to its own registry and model, disable banana until its model exists, and surface inference failures (`#100`).
- Replaced `android-actions/setup-android@v3` in `.github/workflows/release.yml` with preinstalled `$ANDROID_HOME` license acceptance (avoiding removed `sdkmanager tools` failure on Command-Line Tools 16.0), added `scripts/` to `ml` Mypy CI check, and pointed `.github/dependabot.yml` at `develop` and root `pnpm` workspace.
